# PostgreSQL CNPG Restore Procedure

## Prerequisites
- Access to the Kubernetes cluster with `kubectl` and `cnpg` plugin installed.
- Backup files accessible (S3 bucket or NFS share).

## Steps

1. List available backups:
   ```bash
   kubectl cnpg backups list odoo-db -n backend

    Choose a backup (e.g., odoo-db-daily-20260513020000).

    Create a restore cluster manifest (restore-cluster.yaml):
    yaml

    apiVersion: postgresql.cnpg.io/v1
    kind: Cluster
    metadata:
      name: odoo-db-restored
      namespace: backend
    spec:
      instances: 3
      storage:
        size: 100Gi
      bootstrap:
        recovery:
          backup:
            name: odoo-db-daily-20260513020000
          recoveryTarget:
            targetTime: "2026-05-13T02:00:00Z"
      externalClusters:
        - name: original-cluster
          barmanObjectStore:
            destinationPath: s3://your-bucket/           # same as original
            s3Credentials:
              accessKeyId:
                name: s3-creds
                key: ACCESS_KEY_ID
              secretAccessKey:
                name: s3-creds
                key: ACCESS_SECRET

    Apply the manifest:
    bash

    kubectl apply -f restore-cluster.yaml

    Wait for the cluster to be ready:
    bash

    kubectl wait --for=condition=ready cluster/odoo-db-restored -n backend --timeout=600s

    Update the Odoo Deployment to point to the restored cluster's read-write service:
    yaml

    env:
      - name: HOST
        value: odoo-db-restored-rw.backend.svc.cluster.local

    Verify data and remove the old cluster if no longer needed.

Important: Always test restore in a non-production environment first.
